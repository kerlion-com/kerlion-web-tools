فاحص بيانات JSON-LD من KERLION

افحص صيغة بيانات JSON-LD، واكتشف أخطاء JSON الشائعة، وراجع وجود السياق والنوع وبعض الخصائص المهمة. الصق البيانات مباشرة أو الصق كود script الذي يحتوي عليها، ثم اعرض تقرير الفحص.

أدخل بيانات JSON-LD

يمكنك لصق كائن JSON-LD مباشرة أو لصق وسم script كاملا. تفحص الأداة صيغة JSON محليا، وتقدم ملاحظات بنيوية تساعدك على مراجعة البيانات قبل استخدامها.

يمكن فحص بيانات JSON-LD مباشرة أو استخراجها من وسم script من نوع application/ld+json. لا تلصق بيانات خاصة أو حساسة.

مهم: هذا الفاحص يراجع صحة صيغة JSON وبنية JSON-LD وبعض الخصائص الشائعة. لا يمثل اختبار Google الرسمي للنتائج المنسقة، ولا يضمن ظهور مظهر غني في البحث. بعد إصلاح الأخطاء، اختبر الصفحة المنشورة بأداة Google المناسبة وتأكد أن البيانات تطابق محتوى الصفحة المرئي.

مميزات فاحص JSON-LD من KERLION

راجع الأخطاء والملاحظات الأساسية في مكان واحد، مع تقرير واضح يساعدك على تحديد الخطوة التالية.

فحص صيغة JSON

يكشف أخطاء الصيغة الشائعة مثل الفواصل الزائدة أو علامات الاقتباس الناقصة أو الأقواس غير المكتملة.

مراجعة السياق والنوع

يراجع وجود @context و@type، ويعرض الأنواع التي اكتشفها داخل الكائن أو داخل @graph.

ملاحظات حسب نوع البيانات

يقترح مراجعة خصائص شائعة في المقالات والمنتجات والفعاليات والمنظمات ومسارات التنقل، دون اعتبار كل ملاحظة خطأ مؤكدا.

تنسيق ونسخ التقرير

نسق JSON أو اضغطه، وانسخ تقرير الفحص لمراجعته أو مشاركته مع المطور الذي يعمل على الموقع.

طريقة استخدام الأداة

اتبع هذه الخطوات لمراجعة بياناتك بشكل واضح قبل نشرها.

1

الصق البيانات

الصق كود JSON-LD أو وسم script الذي يحتوي على البيانات في مربع الإدخال.

2

شغل الفحص

اضغط فحص البيانات واقرأ ملخص الصيغة والسياق والأنواع والملاحظات الظاهرة.

3

أصلح ثم اختبر

صحح الأخطاء، ثم افحص البيانات مرة أخرى. بعد ذلك اختبر الصفحة المنشورة بأداة Google الرسمية إذا كان هدفك النتائج المنسقة.

فتح اختبار النتائج المنسقة من Google

الأسئلة الشائعة حول JSON-LD

إجابات عن الفحص المحلي والخصائص والفرق بين صحة الصيغة وظهور النتائج المنسقة.

ما المقصود ببيانات JSON-LD؟

JSON-LD طريقة لتمثيل البيانات المنظمة بصيغة JSON وربطها بمفردات مثل Schema.org حتى تتمكن الأنظمة من فهم معلومات الصفحة بشكل أوضح.

ما الفرق بين JSON وJSON-LD؟

JSON صيغة عامة لتبادل البيانات. أما JSON-LD فيستخدم بنية JSON مع مفاتيح مثل @context و@type لتحديد معنى البيانات وربطها بمفردات منظمة.

هل يكفي أن تكون صيغة JSON صحيحة؟

صحة JSON خطوة أساسية لكنها لا تثبت وحدها أن البيانات مناسبة لنوع Schema.org أو مستوفية متطلبات ميزة محددة في Google. قد تحتاج إلى مراجعة الخصائص والسياسات والصفحة المنشورة.

لماذا تظهر ملاحظات على خصائص البيانات؟

تقدم الأداة اقتراحات أولية حول خصائص شائعة حسب النوع المكتشف. ليست كل خاصية مقترحة إلزامية في كل حالة، لذلك راجع نوع البيانات والغرض منها قبل تعديلها.

هل يفحص الفاحص الصفحة المنشورة على الإنترنت؟

لا، يفحص الكود الذي تلصقه في الأداة. لا يزور عنوان الصفحة ولا يفحص نسخة الكود الموجودة فعليا في الموقع أو البيانات المخزنة مؤقتا لدى Google.

هل يضمن الفحص ظهور نتيجة منسقة في Google؟

لا. ظهور النتائج المنسقة يعتمد على نوع الميزة وأهلية الصفحة وجودة البيانات وسياسات Google، وحتى البيانات الصحيحة قد لا تظهر بشكل غني في نتائج البحث.

أين أختبر أهلية الصفحة للنتائج المنسقة؟

بعد فحص الصيغة، اختبر عنوان الصفحة المنشورة أو الكود باستخدام اختبار النتائج المنسقة من Google، ثم راجع تقرير الفهرسة والتحسينات المتاح في Search Console عند انطباقه.
